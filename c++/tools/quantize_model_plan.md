# Quantize ONNX to Vivante .nb — Plan

## Overview

This document describes how to convert `c++/data/model/yolov5m.onnx`
to a Vivante NPU binary (`yolov5m.nb`) using Acuity Toolkit 5.24.6.
The target quantization is uint8 asymmetric affine, which matches the
ovxlib 1.1.31 runtime used in `c++/reference/yolov3_camera_dc/vip/`.

---

## Tool Requirements

| Tool | Version | Notes |
|------|---------|-------|
| Acuity Toolkit | 5.24.6 | Must match ovxlib 1.1.31 exactly |
| ovxlib | 1.1.31 | Vivante VIP SDK runtime library |
| Python | 3.6 | Acuity scripts require Python 3.6 |
| numpy | 1.19.x | Must be compatible with Acuity environment |
| onnx | 1.9.x | Acuity 5.24 supports ONNX opset ≤ 12 |

> **Important**: Acuity 5.24.6 supports ONNX opset up to 12.
> The ONNX model produced in Phase 0.1 must therefore be generated
> with `--opset 12` if targeting Acuity directly.
> Re-run tf2onnx with `--opset 12` if the opset 14 model is rejected.

---

## Quantization Configuration

Acuity uses a JSON configuration file to control the quantization pass.

Save the following as `c++/tools/yolov5m_quantize.json`:

```json
{
  "model": {
    "input_file": "c++/data/model/yolov5m.onnx",
    "output_file": "c++/data/model/yolov5m.nb",
    "model_type": "onnx"
  },
  "inputs": [
    {
      "name": "input_1",
      "shape": [1, 640, 640, 3],
      "dtype": "uint8",
      "format": "NV12",
      "preprocess": {
        "mean": [0, 0, 0],
        "scale": 0.003921569,
        "color_space_convert": "NV12_to_RGB"
      }
    }
  ],
  "quantization": {
    "type": "asymmetric_affine",
    "dtype": "uint8",
    "iterations": 1,
    "rebuild_model": true
  },
  "calibration": {
    "dataset_path": "VOCdevkit/VOC2007/JPEGImages/",
    "num_images": -1,
    "resize_to_input": true,
    "letterbox_fill": 128
  }
}
```

### Key Configuration Fields

| Field | Value | Rationale |
|-------|-------|-----------|
| `scale` | `0.003921569` | `1/255.0` — matches Python `pixel / 255.0` normalization |
| `color_space_convert` | `NV12_to_RGB` | Camera produces NV12; NPU graph folds conversion |
| `type` | `asymmetric_affine` | Standard uint8 per-tensor quantization |
| `dtype` | `uint8` | Matches reference `vnn_yolov3uint8.h` naming convention |
| `num_images` | `-1` | Use the full test set for calibration |

---

## Calibration Dataset

Use the full `VOCdevkit/VOC2007/JPEGImages/` directory (all JPEG
images in the test split).  The calibration set should cover all
five target classes (ship, aircraft, roof, car, oiltank) for
representative activation statistics.

Recommended minimum: 500 images.  Using the full set is preferred
to avoid under-sampling rare classes such as `oiltank`.

If the full set is too large for the calibration machine:
- Use a stratified sample: at least 100 images per class.
- Keep the same letterbox preprocessing (640×640, gray fill 128).

## YOLOv5 Special Operators

Two operators require explicit handling before Acuity conversion:

### Focus Layer → SpaceToDepth + Split + Concat

Acuity 5.24 does not support the strided-slice concatenation pattern
generated by the Focus custom layer.

**Required pre-processing step** (do once before conversion):

1. Export the ONNX with the Focus layer already replaced by
   `SpaceToDepth` (block_size=2) followed by a channel-reorder
   `Gather` op.  This was described in Phase 0.1.
2. Verify the replacement is correct (max diff < 1e-4 vs original).
3. Pass this modified ONNX to Acuity.

If Acuity still rejects `SpaceToDepth`, fall back to the explicit
three-op sequence: `Slice` (4 slices) → `Split` → `Concat`.
This is universally supported in all Acuity versions.

### SiLU Activation → check Acuity support

Acuity 5.24.6 does **not** have a native SiLU/Swish op.
The `Mul(x, Sigmoid(x))` pattern from opset 12 ONNX is recognized
and fused by Acuity's pattern-matching pass.

Validation: after conversion inspect the `.nb` model log for
`VX_KERNEL_SiLU` or `VX_KERNEL_Swish` entries.  If they are absent,
the fused op is missing and accuracy will degrade.

Mitigation if SiLU fusion fails:
- Replace all SiLU activations with `HardSwish` before tf2onnx
  export (see Phase 0.1 mitigation table).
- HardSwish is directly supported in Acuity 5.24 via
  `VX_KERNEL_HardSwish`.

## Conversion Command

```bash
# Activate the Acuity 5.24.6 Python environment
source /opt/acuity-5.24.6/setup.sh

# Run quantization conversion
acuitynet \
  --config    c++/tools/yolov5m_quantize.json \
  --verbose

# Expected output files:
#   c++/data/model/yolov5m.nb          ← NPU binary (equivalent of vnn_yolov3uint8 .nb)
#   c++/data/model/yolov5m_quant.onnx  ← Quantized ONNX for inspection (optional)
#   c++/data/model/yolov5m_info.json   ← Per-tensor quantization parameters
```

Alternatively, use the Acuity Python API directly:

```python
from acuitynet.core import AcuityNet

net = AcuityNet()
net.load_model(
    model_file='c++/data/model/yolov5m.onnx',
    model_type='onnx'
)
net.quantize(
    calib_dataset='VOCdevkit/VOC2007/JPEGImages/',
    quantize_type='asymmetric_affine',
    dtype='uint8',
    input_meta={
        'name': 'input_1',
        'mean': [0, 0, 0],
        'scale': 0.003921569,
        'color_space': 'NV12'
    }
)
net.export(output_file='c++/data/model/yolov5m.nb')
```

## Output Artifacts

| File | Description | Reference equivalent |
|------|-------------|----------------------|
| `c++/data/model/yolov5m.nb` | Vivante NPU binary | `vnn_yolov3uint8.nb` in reference code |
| `c++/data/model/yolov5m.nb.h` | C header with model metadata | `vnn_yolov3uint8.h` in reference code |
| `c++/data/model/yolov5m.nb.o` | Pre-linked object | `vnn_yolov3uint8.o` in reference code |

The `.nb.h` file contains the `vnn_CreateYolov5mUint8_NB()` entry
point that replaces `vnn_CreateYolov3TinyUint8_NB()` from the
reference code.

## Accuracy Validation

### Target

| Metric | Baseline (Python TF) | Target (NPU uint8) |
|--------|---------------------|--------------------|
| mAP@0.5 | 90.53% | ≥ 89.00% |
| Acceptable drop | — | ≤ 1.53% |

### Validation Procedure

1. Run the original Python evaluation script on the full VOC2007
   test set using the `.h5` model:

   ```bash
   python get_map.py  # baseline: 90.53% mAP
   ```

2. Run the same evaluation using onnxruntime on the quantized
   `.onnx` model (before NPU compilation):

   ```bash
   python get_map.py --model c++/data/model/yolov5m_quant.onnx
   ```

   Expected: ≥ 89.50% mAP (most quantization loss occurs in
   float→int8 step, not in NPU execution).

3. Deploy `yolov5m.nb` to the target ARM SoC and run:

   ```bash
   ./multimodal_detect --model c++/data/model/yolov5m.nb --eval
   ```

   Expected: ≥ 89.00% mAP.

### Mitigation if Accuracy Drops Below 89%

Apply mixed-precision quantization: keep the first and last
convolutional layers in int16, all middle layers in uint8.

```json
{
  "quantization": {
    "type": "asymmetric_affine",
    "dtype": "uint8",
    "per_layer_override": {
      "model/darknet/focus/conv2d/BiasAdd": {"dtype": "int16"},
      "model/detect_0/conv2d/BiasAdd":      {"dtype": "int16"},
      "model/detect_1/conv2d/BiasAdd":      {"dtype": "int16"},
      "model/detect_2/conv2d/BiasAdd":      {"dtype": "int16"}
    }
  }
}
```

Layer names must be verified from the `.nb_info.json` output of the
initial conversion run.

If mAP is still below 89% after mixed precision:
1. Increase calibration dataset to the full JPEG set.
2. Try per-channel quantization (`"per_channel": true`).
3. File a bug against Acuity 5.24 SiLU fusion and apply the
   HardSwish fallback from Phase 0.1.

## Notes on Reference Code Compatibility

The reference code (`c++/reference/yolov3_camera_dc/vip/`) was
designed for YOLOv3 tiny uint8.  The YOLOv5m `.nb` produced here
is a drop-in replacement at the binary level, but the following
call sites must be updated:

| Reference symbol | YOLOv5m replacement |
|-----------------|---------------------|
| `vnn_CreateYolov3TinyUint8_NB` | `vnn_CreateYolov5mUint8_NB` |
| Output tensor IDs (3 tensors) | Same count, different tensor names |
| Postprocess decode formula | YOLOv5 formula (see Phase 0.3 plan) |

The FIFO async inference pattern in `fifo.h` and the
`vsi_nn_DtypeToFloat32` de-quantization call are reused unchanged.
