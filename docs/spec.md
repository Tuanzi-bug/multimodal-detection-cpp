# 需求规格说明书（Spec）

## 项目背景

将现有 Python/TensorFlow 多模态目标检测系统移植到 C++，部署到 ARM 单片机（搭载 Vivante GPU 的 SoC）。

## 系统概述

两阶段融合检测流水线：
1. **YOLOv5m**：对 RGB 图像进行初步目标检测
2. **ACE 算法**：对注册配准的高光谱图像做光谱确认
3. **融合模块**：用光谱结果过滤 YOLO 检测，提升 mAP（90.53% → 92.34%）

## 检测类别

| 类别 | 编号 |
|------|------|
| aircraft（飞机）| 0 |
| car（汽车）| 1 |
| oiltank（油罐）| 2 |
| roof（屋顶）| 3 |
| ship（船舶）| 4 |

## 功能需求

| ID | 需求 |
|----|------|
| F1 | 对 640×640 RGB 图像运行 YOLOv5m 推理，输出带类别的检测框 |
| F2 | 实现 ACE（自适应一致性估计器）算法处理高光谱数据立方体 |
| F3 | 实现逐列 min-max 归一化（对应 sklearn minmax_scale） |
| F4 | 加载预计算光谱库矩阵（每类 131×129，共 21 个文件） |
| F5 | 多模态融合：用中心/十字截面 ACE 阈值（≥80%）过滤 YOLO 检测框 |
| F6 | 支持 3×3 核形态学膨胀 + 1.3× 对比度增强处理 ACE 图 |
| F7 | 支持 NV12 和 RGB888 输入格式（适配相机流水线） |
| F8 | 在 ARM Cortex-A + Vivante NPU 的资源受限环境下运行 |

## 非功能需求

| ID | 需求 |
|----|------|
| NF1 | 所有 C++ 代码放在 `c++/` 目录 |
| NF2 | 使用 Docker 进行 ARM 交叉编译 |
| NF3 | 参考 `c++/reference/yolov3_camera_dc/vip/` 中的实现模式 |
| NF4 | 全程使用 git + gh 进行版本管理 |
| NF5 | 目标推理延迟：YOLO < 100ms，ACE < 50ms，端到端 < 200ms |
| NF6 | C++17 标准，-O2 优化 |
| NF7 | 文件不超过 800 行，函数不超过 50 行 |

## 关键参数（来自 Python 源码）

```
YOLO 输入尺寸：640×640
锚框（9个）：[10,13],[16,30],[33,23],[30,61],[62,45],[59,119],[116,90],[156,198],[373,326]
锚框分配：[[6,7,8],[3,4,5],[0,1,2]]

```

## 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| 线性代数 | Eigen 3.x（header-only） | 无需共享库，支持 ARM NEON，嵌入式友好 |
| 图像处理 | OpenCV（target 预装版） | `cv::dilate` 直接对应 Python `cv2.dilate` |
| NPU 推理 | Vivante OpenVX SDK | 与 reference 代码一致，已有 YOLOv3 示例 |
| 数据格式 | 预转换为 .bin | 避免在目标设备解析 .mat |
| 构建系统 | CMake + ARM 交叉编译 | 比 Makefile 更可维护 |

## 验收标准

- [ ] YOLO 仅检测 mAP ≥ 89%（Python 基准 90.53%，允许 1.5% 量化损失）
- [ ] 多模态融合 mAP ≥ 91%（Python 基准 92.34%）
- [ ] 所有单元测试通过
- [ ] Docker 交叉编译成功，产出 ARM 可执行文件
- [ ] 端到端延迟 < 200ms（目标硬件）
